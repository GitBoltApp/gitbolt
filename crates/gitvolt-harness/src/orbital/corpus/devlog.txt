# The first devlog

We said we would write one of these every month. This is the first, and there is not much to
show yet, so it is short and has no pictures. There is nothing to take a picture of.

What exists is a Cargo workspace with a licence (MIT), a pinned toolchain (Rust 1.85) and
rustfmt set to the 2024 edition. Ilse set that up before anything else, so nobody has to argue
about formatting later. The core crate is there with its manifest, and the game and render crates
come after it.

The only code in review is Teodor's maths helpers, on `feature/core-math`: wrapping an angle into
one turn, linear interpolation, smoothstep, each with a test. It is the dullest merge request we
will ever have, and the orbit code will lean on all of it.

I added the template you can see in `docs/devlog/`. It has a slot for an image, and a reminder to
say what is not done, so nobody reads a half-built feature as finished.

- Noor starts on the bodies: a position, a velocity, a mass and a radius for each.
- I will write down the units in the core's docs. Kilometres, seconds and tonnes, with angles in
  radians, so that a number in the code means one thing.

# A world that steps

There is still nothing to fly, but the core can run a world now. Bodies exist (a planet, a moon
and a ship, each with a position, a velocity, a mass and a radius), and the world keeps them in
one list. Ilse added gravity, summed over every body, and I put the fixed-step clock and the
integrator under it.

The clock matters more than it sounds. Frame time goes in and whole physics ticks come out, with a
cap on the ticks one frame may run, so a long stall can't freeze the window. The leftover is
capped as well, because it grew without bound while the tick cap held the ticks back.
Noor also fixed the drift on long runs: the integrator moved the position from the old velocity,
and orbits spiralled outwards. The velocity updates first now.

Gravity got a softening term. A ship that passed through the middle of a planet used to come out
at an absurd speed, because the force goes to infinity at zero distance. Now it stays finite.

A few things around the physics landed too:

- CI runs the tests and clippy on every push (Wen).
- Clippy's pedantic lints are on for the core.
- Kasimir's window opens, runs the game loop and clears to a dark colour each frame. That is the
  whole picture, for now.
- Rafe's note on the units is in the crate docs.

## What comes next

The camera is next, following the ship, and then Ilse's first planet sprite so the window has
something in it. I want to predict an orbit a few hundred ticks ahead, which needs the orbit's
elements worked out from a ship's state. No MR for that yet.

# Docking at the Ring

You can dock now. The Ring Station sits on the inner orbit, with four docking ports, and a ship
that is close enough and slow enough to a free port starts to latch. After a few seconds of
holding that, it docks and stops, and the docked screen opens. U undocks, and the port is free
again. A ship that drifts off while latching stops latching, so a bad approach just means trying
again.

The speed limit was the argument. Ilse made it a named constant with a test, and it has been
nudged since, so check the constant, not this post.

Around it:

- Noor drew the ring station sprite, which went in with Teodor's station code.
- The cargo hold is in, with ten tonnes to a slot, and so is the first design document (Rafe).
- The explosion sprite and sound are in the repository, and so is the mining laser sound. None
  of them plays yet, because nothing explodes or mines.
- The prospector sprite is drawn. It is in the repository and has no shipyard to stand in.

Kasimir's mining laser is the open branch. It cuts the laser's range to 40 units, and so far it
picks the rocks in range. Taking ore out of them and into the hold is the next commit. It is
not in main yet.

# Buying and selling

There is an economy, a small one. The market is in main: a commodity table of twelve goods, and a
market at each station that prices a good from its stock. Buy a tonne and the price rises a
little. Sell one and it falls. A station that has been sold a lot of ore pays less for the next
tonne, which is the whole game in one sentence.

Kasimir's trade screen is how you use it. Dock at a station and it shows the goods, with the
prices from the commodity table. The ship carries its credits.

| Key | What it does |
| --- | --- |
| B | buy a tonne of the selected good |
| S | sell a tonne of it |
| U | undock |

Teodor fixed a small thing: the docking chime played twice on one visit. It plays once per visit
now.

Two branches are open as I write:

- **save-files** (Teodor) writes the game to a file. It starts with the magic `ORBS`, carries a
  checksum so a damaged file can't load, and is written through a temporary file and then
  renamed, so a crash mid-save leaves the old save alone. It is not in main yet.
- **ui-icons** (Noor) is eight icons for the HUD: fuel, cargo, map, trade, dock, mine, target and
  settings. The painter and the colours they need came with it.

The prices have not been balanced. Anyone can find a loop that pays too well, and we would like to
hear about it, so we know which one to close first.

# The settings menu

There is a settings menu now, on the title screen. It is small on purpose, with three rows:

- **Music**: a volume in percent. Left and right move it, and it starts at forty.
- **Thrust key**: press Enter on it and the next key you press becomes the thrust key.
- **Back**: leaves the screen.

The thrust key reads from a copy of the key table that the menu can change, so the key you pick is
the key the flight uses. Rebinding moves only that control. If the key you choose is already bound to
something else, the table has two rows for it, and that needs a rule.

The music row has nothing to play yet. The menu track isn't written, and the audio device is still
a stub that logs what it would play. We put the row in now so the settings file has the key from
the start.

The first version forgot everything when you quit. Wen fixed it: the settings are written to
`saves/settings.cfg` when you leave the screen.

  changes (Noor, Ilse).

# Systems run the world

The world is a set of tables, one per kind of data, and every object is an id that indexes into
each table. Before this, the bodies were one list that every piece of code walked in its own way.
That made the mining code reach into the ship, and the ship code reach into the rocks, and neither
could be tested alone.

Physics and mining are systems now, along with thrust, collisions, docking and the market's drift
back towards its usual stock. Each one takes the tables it needs, and the game calls them once a
tick, in a fixed order, so the result doesn't depend on which object a loop happened to visit
first. Each can also be tested against a world built in three lines. The first test we wrote that
way found the bug below.

Ilse found it. The loop over the table stopped one short, so the last entity in it was never
visited. The rocks are spawned last, so the last rock never pulled on the ship. Nobody would have
noticed, which is the worrying part.

Saving got three things:

- An autosave, every five minutes, into its own slot, so it never overwrites a save you made.
  Continue on the title screen reads that slot (Kasimir).
- A file that ends early is now an error, not a crash (Wen). A file too short to hold a checksum is
  refused before it is read.
- A sample save, `saves/sample.orbsave`, and a document of the format, `docs/saves.md`. Attach the
  sample to a bug report if you cannot reproduce something.

The diff is larger than the change: most of the lines moved, and few of them changed meaning.

## What comes next

The economy and contracts can be systems too. Contracts are not designed yet. Teodor has an idea
for a multiplayer prototype and will start on it on a branch.

# Bloom, trails and a branch

The render crate had a good month. A bloom pass now glows over the bright parts of the frame,
mostly the thruster. It was washing out the ship at full thrust, so the glow is dimmer, and Rafe
capped it at two passes a frame to keep it cheap on the laptops we test on.

Wen made shaders reload without restarting the game: F5 rebuilds the sprite pipeline from
`sprite.wgsl` on disk. Only the sprite shader reloads so far, and a shader that doesn't compile
still stops the game with the compiler's message. Catching that and keeping the old pipeline is
the next step.

Bodies leave a trail. Each body's orbit trail holds its last 300 ticks, and the oldest point
drops off as a new one is added, so it can't grow over a long session. A bug went in with it and
came out again. When the fade's two edges matched, the fade range was zero, and every point
vanished. Rafe found it, and a zero-width range draws at full strength now.

F3 toggles a frame-time overlay, a bar against the 60 frames a second budget, green under and red
over. The app loop doesn't draw it yet, so F3 changes nothing you can see.

## The experiment branch

`experiment/multiplayer` is mine, and it is not going to main. It is a lockstep prototype. Each
peer sends its inputs a few ticks ahead, and every peer steps the same simulation, so the
state only has to agree and doesn't need sending. There is a checksum of the simulation, so a
desync shows up at once. A longer delay is there for slow links.

## What comes next

Menu music and sound routing (Wen, Kasimir), and a second look at the debug overlay.

# The menu track

The title screen has music, at least on paper: a short loop, `menu-loop.ogg`, with a
sample-accurate loop point so it doesn't click when it comes round. The mixer holds its level, the
music slider in the settings scales it, and it fades out over two seconds once a game starts
(Rafe's part).

That last part has a catch we should say out loud. The audio device is still the stub from the
engine hum: it writes what it would play to the log, at trace level. So the mixing work this month
is real, and you can watch it in the log, but you can't hear it in the build yet. The loop itself
we tested the old way, in an audio editor, for longer than anyone should listen to a loop.

Sounds are routed to buses now (Kasimir). The music has its own level, and every effect plays on
one of two buses:

| Bus | Sounds |
| --- | --- |
| Effects | the engine hum, the laser, the docking chime, the cargo clank |
| Interface | the menu click |

So the click on a menu button no longer shares a level with the engine.

![The title screen the track plays under](../../assets/title/title.png)

Ilse added the courier to the ship table, with its own sprite. The table gained a price column for
every class, ready for the day there is a shipyard.

On the multiplayer branch, Teodor has a lobby: two players at most, each with a name and a ready
flag, and the game starts when both are ready. It is on `experiment/multiplayer`, not in main.

# Sound levels and a save format

We balanced the sounds against each other. The menu music now sits about six decibels under the
effects. The numbers are constants at the top of `audio.rs`, `MUSIC_VOLUME`, `EFFECTS_GAIN` and
`INTERFACE_GAIN`, with a comment on each, so the next person who wants to change one can see the
reason behind it. A test checks the six decibels.

Wen reworked three of the samples:

- **The engine hum** has a pitch that follows the load.
- **The mining laser** is shorter, so it doesn't drone while you hold on a rock.
- **The docking chime** starts as the ship first touches the port, so it ends as the clamps close
  rather than after them.

The mixer also stopped queueing a sound twice: a sound asked for again before the device takes
the queue now plays once. As before, the device is a stub, so all of this shows in the trace log
and not in your speakers.

The save format moved to version two. A version two file stores the time the game was started, and
the ship's fuel and hull. Version one left those out, so a loaded game used to come back with a
full tank and a fresh hull. Old saves still load. I wrote the migration: they are upgraded in
memory and written back as version two the next time the game saves. Rafe updated the sample save
to match.

The scout, the hauler and the interceptor have their new hull (Noor), and the Ring Station has
been redrawn to match it.

# Contracts

Contracts are in the core. A contract asks for some tonnes of one good at another station by a
deadline, pays on delivery, and expires when the deadline passes. Missing one costs you the pay
and nothing else, so a missed contract is a lesson rather than a punishment. A station keeps at
most five open at once.

Docking at the destination pays out every contract due there whose goods are in the hold, and takes
the goods.

The pay follows the distance and the urgency (Ilse). A far delivery pays more than a near one, and
a short deadline pays more than a long one, up to twice the distance rate for a rush job. A
contract with six days or fewer left counts as urgent. We tuned it on a few routes and then left
the numbers alone, because a route nobody tries is not worth tuning for.

Deadlines count in game days, which are a little under fifteen minutes of flying. They do not
count while the game is paused, and P pauses the flight now. Rafe caught that one: a player who
paused to read something could come back to a contract that had expired while they were away.

- The game has a new icon with a heavier outline, and the fuel icon is redrawn (Noor).

  contracts on the docked screen and C accepts the first one.

  has arrived.

# Thrust on the stick

The left stick steers and thrusts now. Push it forward to thrust, and left or right to turn.
Thrust is analogue, so a half press gives half thrust, and the ship responds to the stick the way

# Contracts in the save

Open contracts are saved now. The save format is version three. Contracts are stored as a list,
with their deadlines in ticks, so a loaded game picks up exactly where the clock was. A contract
that was due in an hour is still due in an hour after a reload.

nothing was stored in them. The sample save has two open contracts now, and the documentation for
the format has a table, because a table is easier to check against the code than a paragraph.

look their text up by key, and a key with no text shows itself on screen, so a missing string is

- Far bodies are summed on a coarser grid, which halves the cost of the gravity step. Near bodies

# Verlet and a stub planner

The orbit predictor and gravity run on a velocity Verlet step now. Each body remembers its last
acceleration, and the step uses it for the next position. The step before it was a plain Euler
one with the velocity updated first, which is stable enough for orbits, but its error is first
order, so a long orbit wanders. Verlet's is second order. The first version ignored the
timestep, and Kasimir caught it. Rafe's test is the one that checks the energy over a long orbit.

The autopilot needs a path planner, and the planner is not finished. For now it is a stub. It
returns a straight-line route from the ship to the target, and it does that every time, without
looking at the bodies in the way. That is wrong, and we know it is wrong. A straight line through
a planet is a bad route. The stub is there so the rest of the autopilot can be written against a
real interface, and the planner can land behind it without touching the callers.

| | Euler, velocity first | Velocity Verlet |
| --- | --- | --- |
| Error per step | first order | second order |
| Force sums per tick | one | one |
| Extra state per body | none | the last acceleration |

# Transfer burns

The core can plan a transfer now. Given the radius of the orbit you are on and the one you want,
it works out the two burns of a Hohmann transfer: one to leave the first orbit and one to join the
second, each from the vis-viva speeds at the two ends. The sums are small and old, and they have
tests against the circular speeds they should give.

The clock gained a time warp for the coast between the burns, in four steps, so a long transfer
doesn't mean watching the ship drift for ten real minutes. The autopilot can set it.

The autopilot that flies the burns is not in main. Kasimir has two commits of it on his machine,
unpushed. It plans the burns from the orbit the ship is actually in, and it stops firing once the
burn is paid. It comes in when it handles the drift a long transfer picks up. The planner stub
stays until then.
